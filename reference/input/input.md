# Input

What the player did, settled onto the engine's frame boundary.

**Not written, and not yet writable.** Input is next in line for the full
porting process, so its design is about to move — documenting it now would
formalise a moving target and split the reasoning away from code that is
still being changed. The record stays inline and in `docs/bps/` until the
port settles.

This page exists so the chapters that hand work over to input have somewhere
to point. It is a marker, not a brief: what the subject owes gets written
after the port, not before.

`docs/bps/` holds the standing authority meanwhile — `INPUT_STREAM.md` for
the stream and the frame cut, with `KEYBOARD.md`, `MOUSE.md`,
`CONTROLLERS.md` and `MIDI_INPUT.md` (quarantined) beside it.

Its own folder when the time comes: the stream, the keyboard, the pointer,
controllers and text each earn a page.
